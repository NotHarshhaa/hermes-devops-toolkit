Planned skills

Two focused skills to start

Each skill is a folder with a SKILL.md of instructions that Hermes Agent loads when relevant. Small, modular, evidence-based.

skills/pipeline-failure-translator Planned

Pipeline Failure Translator

Analyzes Jenkins and GitHub Actions failure logs, pinpoints the failing stage and the error that matters in the noise, explains likely root causes in plain language, and suggests fixes plus verification steps.

  • Find the one error that actually failed the run
  • Separate observed errors from hypotheses
  • Recommend read-only checks before changes
skills/kube-explain Planned

KubeExplain

Explains common Kubernetes failure states — CrashLoopBackOff, ImagePullBackOff, Pending — from your kubectl describe output, events, and logs, then recommends the next most useful diagnostic command.

  • Interpret describe output, events, and logs
  • Pull failures, crash loops, scheduling problems
  • Potential fixes and their risks

Principles

Small tools, honest diagnostics

What the toolkit is designed around — one problem, one focused skill, one practical solution at a time.

  • #1 Diagnose

    Focus on the real error

    Logs are noise. Skills are designed to find the failing stage and the line that actually matters.

  • #2 Explain

    Plain-language causes

    Likely root causes in words engineers use — not opaque error codes left to interpretation.

  • #3 Verify

    Next steps you can run

    Targeted remediation plus the commands or tests that confirm the fix actually worked.

  • #4 Stay Safe

    Safe by default

    Read-only diagnostics first. Destructive or production-affecting actions require explicit approval.

  • #5 Extend

    Built to grow

    A consistent skill format makes it straightforward to add more DevOps and cloud skills.

  • #6 Contribute

    Community-driven

    Honest examples, reproducible scenarios, and contributions are welcome from day one.

How it works

From evidence to answer in five steps

  1. 1

    Invoke the skill

    You ask, or Hermes Agent selects the relevant skill for the problem at hand.

  2. 2

    Provide evidence

    Paste logs, command output, or configuration. Sanitized — see the safety notes below.

  3. 3

    Guided analysis

    Hermes uses its model and enabled tools, guided by the skill’s instructions.

  4. 4

    Get the explanation

    The likely cause, clearly separated from inference, with recommended next steps.

  5. 5

    You decide

    You review every suggestion and choose what to run. The skill assists; you stay in control.

🛡 Security & safety

This toolkit is meant to assist engineers, not replace operational judgment.

Sanitize your logs

CI/CD logs and kubectl output can contain secrets. Never commit credentials, tokens, or kubeconfig files. Sanitize before sharing with any model provider.

Read-only by default

Diagnosis should not change your system. Potentially destructive actions require your explicit approval, every time.

Verify AI output

AI-generated diagnoses can be wrong. Always verify critical findings against the real system state before acting on them.

FAQ

Honest answers first

Is it ready to use?

No. The project is in early development and both skills are planned, not released. Everything described on this page is the design intent, not a finished feature.

Does this work without Hermes Agent?

The skills are written in the standard SKILL.md format for Hermes Agent. Adding support for other agent runtimes is not planned right now.

Is this affiliated with Nous Research?

No. Independent community project, not affiliated with or endorsed by Nous Research. Hermes Agent is a product of Nous Research.

Will it cost anything?

The toolkit is MIT-licensed and will be free. You still pay for your own model provider usage through Hermes Agent.

How can I contribute?

Suggest a specific DevOps problem worth solving, add sanitized troubleshooting examples, improve diagnostic instructions, or write tests for known failure scenarios. See CONTRIBUTING.md in the repository.
